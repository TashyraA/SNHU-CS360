# Event Tracker App – Portfolio Artifact

## Overview
This repository contains my completed Event Tracker mobile application, developed for Project Three in CS 360. The ZIP file in this repository includes both the finalized UI design from Project Two and the full functional code implementation from Project Three.

---

## Reflection

### **1. Summary of Requirements and User Needs**
The Event Tracker app was designed to help users easily log in, manage event information, and receive optional SMS notifications for upcoming events. The main user needs included simple navigation, clear data entry, secure login, and the ability to organize events in a structured way. The app also needed to handle SMS permissions responsibly and continue functioning even if the user denied access.

### **2. Screens and Features Supporting User Needs**
To support these needs, I created three main screens:
- **Login Screen:** Allows users to enter a username and password or create a new account.
- **Event Grid Screen:** Displays events in a grid-like layout with options to add, update, and delete entries.
- **SMS Permission Screen:** Explains SMS notifications and allows users to grant or deny permission.

I designed each screen with a clear visual hierarchy, grouping related elements together and keeping the layout consistent across the app. This helped create a user-centered UI that was easy to understand and navigate.

### **3. My Approach to Coding the App**
I approached development by breaking the project into smaller tasks and completing one feature at a time. I implemented the login logic, then the database operations, and finally the SMS permission handling. Testing each part as I went helped me stay organized and catch issues early. This incremental strategy is something I plan to continue using in future projects.

### **4. Testing and Why It Matters**
I tested the app using the Android Emulator, checking login behavior, database CRUD operations, and SMS permission responses. Testing was important because it revealed layout adjustments I needed to make and helped me confirm that each feature worked correctly before moving on. It also made debugging much easier.

### **5. Innovation and Problem-Solving**
Throughout the project, I had to problem-solve in areas like setting up the SQLite database and handling SMS permissions. I also had to adjust my UI layouts to ensure they followed Android design guidelines and maintained a clear visual flow.

### **6. Areas of Success**
One area where I feel I was particularly successful was creating a clean and intuitive UI that matched user needs. I also demonstrated strong understanding of Android components like activities, layouts, permissions, and database interactions. This project helped me grow both technically and in my ability to design with the user in mind.
